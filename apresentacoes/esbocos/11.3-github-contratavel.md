# 11.3: GitHub Contratável
**Módulo 11: Recolocação / Internacional**

## Esqueleto (o que falar)

- Gancho: "Depois que seu CV passa, tem alguém abrindo seu GitHub agora. E a maioria dos GitHubs, de júnior a sênior, parece um depósito abandonado: 40 repos sem README, forks de tutorial de 2019 e o último commit de 8 meses atrás."
- Desmontar o mito primeiro: você NÃO precisa de contribuição diária nem de projeto open source famoso. Recruiter e tech lead olham por 2-3 minutos. O jogo é curadoria, não volume. Isso vale ainda mais pro júnior: 3 projetos bem cuidados batem 30 mal cuidados.
- Quem olha o quê (dois públicos, dois filtros):
  - **Recruiter** (30 segundos): foto/nome batem com o LinkedIn? Perfil parece ativo? Bio diz o que você faz? É um sinal de vida, não uma auditoria.
  - **Tech lead / entrevistador** (3–5 minutos): abre 1–2 repos pinados. Olha README, estrutura de pastas, qualidade de um arquivo aleatório, testes, mensagens de commit. Procura: "essa pessoa trabalha como eu gostaria que meu time trabalhasse?". Pra vaga júnior, a pergunta muda um pouco: "essa pessoa aprende rápido e termina o que começa?"
- Ideia central: seu GitHub é uma vitrine com 6 espaços (pinned repos). Vitrine se monta, não se acumula, em qualquer nível de carreira.
- O peso do GitHub por nível: pra sênior/lead, o GitHub é um complemento, o peso maior está na experiência. Pra júnior/pleno sem muito histórico de trabalho, o GitHub frequentemente é a PRINCIPAL evidência de capacidade técnica: é onde a vaga que você ainda não teve é substituída pelo projeto que você construiu.
- O plano de arrumação (framework em 4 passos):
  - **Limpar**: arquivar (não deletar) forks de tutorial, projetos mortos, testes de vaga antigos. Perfil com 8 repos vivos > 45 repos zumbis.
  - **Escolher**: 2–3 projetos que sustentam seu posicionamento (o mesmo da 11.1/11.2). Backend? Pine uma API bem estruturada, não seu experimento de frontend de 2020.
  - **Polir cada repo escolhido**: README com o quê/por quê/como rodar/screenshot ou diagrama; estrutura de pastas limpa; testes (mesmo poucos, bem escritos); CI verde com badge; sem `senha123` no histórico.
    - README é o item de maior retorno por hora investida do seu perfil inteiro. É a diferença entre "repo" e "projeto". Vale ainda mais pra quem não tem cargo pra provar competência, o README É a prova.
  - **Perfil**: bio de uma linha alinhada com a headline do LinkedIn, README de perfil curto (quem sou, o que faço, destaques, contato), link pro LinkedIn.
- "Não tenho nenhum projeto apresentável" (comum em júnior, mas não só): duas saídas honestas:
  - Construir UM projeto pequeno e completo (2–4 fins de semana) que simule problema real da sua área: com testes, CI, README, decisões documentadas. Um projeto profissional vale mais que dez TODO-apps. Pra quem está começando, esse projeto é literalmente o substituto da experiência que ainda não existe.
  - Ou documentar profissionalmente algo que você já tem. Frequentemente o projeto existe; o que falta é embalagem.
- Sinal avançado (diferencial pra pleno/sênior mirando lead): repo com ADRs ou mini-RFCs documentando decisões técnicas. Isso grita "pensa além do código" pra quem avalia, quase ninguém faz. Pro júnior, o equivalente é comentar o "porquê" das decisões no próprio README, mostra raciocínio, não só resultado.
- Mensagens de commit contam história: entrevistador experiente lê o log. "fix", "wip", "aaaa" vs. commits descritivos: é amostra grátis de como você trabalha em time, e é um dos sinais mais baratos de avaliar num candidato sem experiência prévia de equipe.
- Aplicando o método: PREPARAR (auditar o próprio perfil com o checklist, 30min) → AGIR (limpar + polir os 2-3 repos-vitrine, 1–2 fins de semana) → MOSTRAR (pinar, linkar no CV e LinkedIn) → OTIMIZAR (antes de cada processo seletivo, revisar a vitrine pro cargo específico).
- Ação prática da aula: hoje, arquivar tudo que você não mostraria numa entrevista. Esta semana, escrever o README completo do seu melhor projeto usando o template. Trazer o link pra revisão.
- Fechamento: ninguém espera um GitHub de mantenedor famoso. Esperam abrir seu perfil e pensar "essa pessoa é organizada, escreve bem e termina o que começa". Isso é 100% alcançável em duas semanas, com 2 anos de carreira ou com 20.

## O que mostrar (complementos visuais)

- Tour gravado: "o que eu olho em 3 minutos no GitHub de um candidato" (na pele de quem já avaliou mais de 100 engenheiros)
- Perfil real antes/depois: depósito de repos vs. vitrine curada com 6 pinned
- Template de README de projeto (o quê / por quê / stack / como rodar / screenshot / decisões)
- Exemplo de README de perfil (profile README) bem feito
- Lado a lado: histórico de commits "wip/fix/aaa" vs. histórico descritivo
- Exemplo de ADR curto dentro de um repo pessoal, e o equivalente simplificado pra quem está começando
- Checklist de auditoria do perfil (bio, pinned, READMEs, CI, segredos vazados, atividade)
